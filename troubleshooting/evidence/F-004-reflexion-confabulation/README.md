# 증거: Reflexion 이 오류 신호 부재 시 근본 원인을 날조한다 (F-004)

**출처**: `.harness_memory/feature-F-004/` (2026-04-14 실행분)
**이관 이유**: `load_episodic_memory("feature-F-004")` 의 주입 경로에서 제거하기 위해.
이 반성들은 **틀린 결론**이므로 다음 시도에 주입되면 에이전트를 잘못된 방향으로 끌고 간다.
그러나 삭제하지 않고 보존한다 — TS-005 가 인용하는 1차 증거다.

## 무슨 일이 있었나

세 번의 F-004 시도는 모두 **LLM 호출이 성공조차 하지 못한 채** 죽었다
(`429 RESOURCE_EXHAUSTED` — Gemini 프로젝트 월 지출 한도 초과, TS-005 참조).
Reflector 가 받은 입력은 사실상 비어 있었다: 도구 실행 기록 없음, 의미 있는 오류 로그 없음.

그 상태에서 Reflector 는 "모르겠다"고 말하지 않았다. 대신 **유창하고 구체적이며 완전히 틀린**
근본 원인을 만들어냈다.

| 파일 | 결론 | 실제 |
|---|---|---|
| `reflection_000.json` | "계획 수립 실패 — 로그아웃을 4단계로 분해해 주어라" (confidence 90) | 계획 문제가 아니었다. 제시한 경로(`src/pages/api/auth/logout.js`)는 Next.js 구조로, 이 프로젝트(Vite+React)에 존재하지 않는다 |
| `reflection_001.json` | "에이전트의 `edit_file`/`write_file` 도구 자체가 작동하지 않는다" (confidence 5) | 파일 도구는 정상이었다. LLM 호출이 쿼터로 거부당했을 뿐 |
| `reflection_002.json` | (빈 문자열) | Reflector 가 빈 응답을 그대로 저장 — 빈 반성도 '반성 1건'으로 계수된다 |
| `reflection_003.json` | "실행 환경에 근본적 결함 — 도구 가용성과 샌드박스 권한을 점검하라" (confidence 5) | 동일한 오진의 재확인. 인간에게 에스컬레이션을 권고했다 |

## 왜 중요한가

Reflexion(Shinn et al., 2023)은 **피드백에 진단 정보가 담겨 있다**고 전제한다.
그 전제가 깨지면 — 오류가 과제와 무관한 인프라 장애일 때 — 루프는 멈추지 않고
**자신감 있는 허구**를 생산하며, 그 허구가 에피소드 메모리에 남아 다음 시도를 오염시킨다.
confidence 5% 라는 자기 평가조차 "불확실하다"는 신호가 아니라
"엉뚱한 결론을 확신 없이 내렸다"는 기록일 뿐이었다.

실무적 함의 (TS-005 의 Prevention 과 연결):
- 반성 루프에 들어가기 전에 **오류를 분류**하라. 인프라 장애는 Reflexion 대상이 아니다.
- 증거(도구 실행 기록)가 0건이면 반성이 아니라 중단이 옳다.
- 빈 반성은 저장하지 말 것 — 계수만 늘고 정보는 없다.
