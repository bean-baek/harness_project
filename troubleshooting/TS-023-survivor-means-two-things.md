## Symptoms
TS-022 가 컬렉션 멤버 제거를 주입하자 `PROTECTED_PATHS` 의 `/`, `/profile`,
`/settings` 가 생존했다. 보고서는 이렇게 출력했다.

```
생존   src/routes.ts:17  컬렉션 멤버 제거 (PROTECTED_PATHS ← '/')
         '/' 를 목록에서 지웠는데 테스트가 전부 통과했다
```

그래서 다음 작업으로 **"`test.each` 에 목록 크기·멤버 단정을 추가해 3건을 잡히게
만들자"** 고 제안했다. 그 제안이 틀렸다.

F-005 의 명세를 읽어보니:

```
description: 인증되지 않은 사용자가 보호된 페이지에 접근 시 로그인으로 리다이렉트된다
steps:
  1. 로그인하지 않은 상태에서 /dashboard에 접속한다
  2. /login 페이지로 리다이렉트됨을 확인한다
  3. 리다이렉트 후 원래 URL이 보존됨을 확인한다 (?redirect=/dashboard)
```

**명세는 `/dashboard` 만 지목한다.** `/`, `/profile`, `/settings` 는 어디에도 없다.
앱이 명세를 넘어 4개를 보호하도록 구현한 것이다.

그 3개를 테스트로 고정하면 **명세에 없는 것을 단정하는 테스트**가 된다 —
TS-014 가 '측정 도구 오류'로 분류해 **고쳤던 바로 그 패턴**이고, 현재 구현을
명세로 승격시키는 순환이다. 측정 도구가 그 순환으로 나를 밀어넣고 있었다.

## Root cause
보고서가 생존을 **한 종류로** 취급했다. 생존은 두 가지 다른 사실을 뭉쳐 놓은 것이었다.

| 생존의 의미 | 올바른 조치 |
|---|---|
| 명세가 그것을 요구한다 | **증거의 공백** — 테스트에 단정을 추가한다 |
| 명세가 요구하지 않는다 | **명세의 공백** — 테스트를 건드리면 TS-014 다 |

둘을 섞어 "생존 = 테스트 보강"으로 읽히게 만들었다. 측정값이 조치를 잘못 지시했다.

이 프로젝트는 같은 실수를 이미 두 번 했다 — TS-016 의 돌연변이 점수는
"남의 파일이 섞인다"는 구분을 빠뜨렸고, TS-022 의 '폐기'는 "타입이 잡았다"를
묻어버렸다. **측정값을 하나의 수로 뭉개면 조치가 틀린다**는 패턴이 세 번째다.

## Fix
### `spec_names()` — 명세가 멤버를 지목하는지 **사실로** 판정
```python
re.search(re.escape(member) + r"(?![A-Za-z0-9_/-])", spec)
```

경계 문자 집합을 **ASCII 로 한정**하는 것이 핵심이다. `\w` 를 쓰면 한국어 명세의
`/dashboard에 접속한다` 에서 `에` 가 단어 문자라 경계로 인정되지 않아 **전부 미매칭**된다
(실측). 반대로 경계를 아예 두지 않으면 멤버 `/` 가 `?redirect=/dashboard` 의 `/` 에
오매칭되어 **전부 '명세에 있음'** 이 된다.

실측 확인:

| 멤버 | F-005 명세 | 판정 |
|---|---|---|
| `/dashboard` | `/dashboard에 접속한다` | 명세에 있음 |
| `/` | — | 명세에 없음 (`?redirect=/dashboard` 에 오매칭 안 됨) |
| `/profile` | — | 명세에 없음 |
| `/settings` | — | 명세에 없음 |

### `out-of-spec` 상태
명세가 지목하지 않는 멤버의 생존은 별도 상태로 분류하고 **점수 분모에서 제외**한다.
증거의 공백이 아니기 때문이다. 보고서는 두 종류를 **다른 블록에** 출력하고
각각의 조치를 명시한다 — 명세 밖 생존에는 "고정이 필요하다고 판단되면 **먼저 명세에
적는다**" 라고 쓴다.

줄 변이에는 적용하지 않는다. 줄에는 명세에서 찾을 이름이 없으므로 **판정할 사실이
없다.** 추측하지 않는다.

### 명세가 비어 있으면 전부 `out-of-spec`
요구의 근거가 없으면 "요구되는데 고정되지 않았다"고 말할 수 없다.
빈 명세로 점수를 내지 않고 `None` 을 돌린다.

## 이것이 게이트를 약화시키는가
아니다. 세 가지가 함께 지킨다.

1. 명세는 이 하네스의 **계약**이다. TS-008 부터 모든 판정의 기준이 명세였다.
   명세 밖의 것을 요구하면 그 기준이 무의미해진다.
2. 명세가 **LLM 이 쓴 것**이라는 외곽 순환은 이미 README 가 인정한 미해결 문제다
   (`inspect --write-draft` 가 사람이 쓰도록 만든 경로). 명세 밖을 면제하는 것이
   그 순환을 **더 나쁘게 만들지 않는다** — 명세는 이미 권위였다.
3. 명세 밖 생존은 **사라지지 않고 보고된다.** "앱이 명세를 넘어 구현했다"는 사실은
   사람이 볼 신호다 — 명세를 보강할지, 구현을 줄일지는 사람이 정한다.

## Prevention
- **생존한 변이를 보고 바로 테스트를 고치지 말 것.** 먼저 "명세가 이것을 요구하는가"를
  묻는다. 요구하지 않는다면 테스트를 추가하는 것이 **순환을 만드는 행위**다.
- **측정값을 하나의 수로 뭉개면 조치가 틀린다.** 이 프로젝트에서 세 번 나왔다 —
  남의 파일이 섞인 돌연변이 점수(TS-016), '폐기'에 묻힌 타입 감지(TS-022),
  그리고 두 종류가 섞인 생존(TS-023). 수치는 **조치가 갈리는 지점마다 쪼개야** 한다.
- **문자열 경계를 다국어 기준으로 검사할 것.** `\w` 는 한글을 단어 문자로 보므로
  한국어 문서에서 경로·식별자 경계 판정에 쓸 수 없다. ASCII 집합을 명시한다.
- **판정할 사실이 없으면 판정하지 말 것.** 줄 변이에는 명세에서 찾을 이름이 없고,
  명세가 비어 있으면 요구의 근거가 없다. 둘 다 추측하지 않고 보류한다.
- **도구가 제안하는 조치를 의심할 것.** 측정 도구가 "생존 = 테스트 보강"으로 읽히게
  만들어 나를 TS-014 의 패턴으로 밀어넣었다. 도구의 출력도 검증 대상이다.
